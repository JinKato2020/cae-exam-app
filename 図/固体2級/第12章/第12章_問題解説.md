## Q 12-1　丸め誤差

**問題**

有限精度の数値表現による丸め誤差の説明はどれか。

**選択肢**

1. メッシュを有限個にする誤差だけ
2. 級数を有限項で打ち切る誤差だけ
3. 演算の正確な実数値を表現可能な近い値へ置き換えることによる誤差
4. 境界条件の仮定による誤差だけ

**正答** 3番：演算の正確な実数値を表現可能な近い値へ置き換えることによる誤差

**解説**

【意味】コンピューターは、無限に続く桁をすべて保存できない。保存できる数の中から値を選び直すと、元の数との差が生じる。これが丸め誤差で、正解は3。例えば10進数で有効数字4桁なら、1/3=0.3333…を0.3333として扱う。実際の2進浮動小数点では、10進数の0.1も有限桁で正確に表せない。
【他の誤差】打切り誤差は、無限級数などを途中で止めるために生じる。離散化誤差は、連続した物体を有限個の要素などで近似するために生じる。モデル化誤差は、実物を理想化した条件との違いから生じる。原因を分けると対策を選びやすい。
【CAEとの関係】数値を倍精度へ変えると丸め誤差を抑えられる場合があるが、粗いメッシュや間違った境界条件まで直るわけではない。丸めには最近接への丸めや切捨てなど複数の方式があり、常に最も近い数へ丸めるとは限らない。

## Q 12-2　計算順序と誤差

**問題**

浮動小数点演算について正しいのはどれか。

**選択肢**

1. 同じ数学的な式でも評価順序や算法で誤差が変わり得る
2. CPUが高速なら同じ精度形式でも必ず誤差が小さい
3. 加算順序は常に無関係
4. 整数の桁あふれは常に実数へ自動変換される

**正答** 1番：同じ数学的な式でも評価順序や算法で誤差が変わり得る

**解説**

【答え】数学の実数計算では(a+b)+c=a+(b+c)だが、有限桁の計算では、途中の丸めで結果が変わることがある。よって1が正しい。
【数字で確認】10進有効数字4桁で毎回四捨五入するとする。(1000+0.1)−1000では、1000.1が1000へ丸められるため、結果は0になる。一方、(1000−1000)+0.1なら結果は0.1。数学的には同じ式でも、小さい0.1を失うかどうかが違う。
【工夫】小さい項をまとめる、補償加算で失われた分を補う、式を安定な形へ変える、といった方法がある。ただし正負が混じる和などでは「小さい順なら必ず最善」とは限らない。
【誤答】整数の桁あふれへの対応は言語や型によって異なり、自動で実数になるとは限らない。CPUの速度は処理の速さであり、同じ精度形式の有効桁数を増やすものではない。

## Q 12-3　整数式の評価

**問題**

整数同士の除算で小数部分を捨てるものとする。全数値・全演算を整数型で行い、通常の括弧と演算優先順位で 1+(1÷2−1)×2+1÷2 を評価する。結果はどれか。

**選択肢**

1. −1
2. 0.5
3. 0
4. 2

**正答** 1番：−1

**解説**

【前提】本問は、全演算を整数型で行い、整数同士の割算では小数部分を捨てる。普段の実数計算の1÷2=0.5とは違い、ここでは1÷2=0である。
【途中式】1+(1÷2−1)×2+1÷2 → 1+(0−1)×2+0 → 1+(−1)×2 → 1−2=−1。括弧を先に、乗除を加減より先に処理するので、正解は1。
【比較】実数で計算すると1+(0.5−1)×2+0.5=0.5となる。差は計算ミスではなく、使う数値型と除算の規則の違いである。
【プログラムの注意】すでに整数除算で0となった結果を実数型へ変えても、失った0.5は戻らない。実数の比を求めたいときは、割算の前に実数型で扱う必要がある。割算記号の仕様は言語ごとに違うため、「プログラムの1/2は必ず0」と一般化しない。

## Q 12-4　有限桁計算の実例

**問題**

10進の有効数字4桁で、各演算後に最も近い値へ丸める。1234+1.987−1233を左から計算した値はどれか。入力は正確とする。

**選択肢**

1. 2.000
2. 2.987
3. 3.000
4. 0

**正答** 3番：3.000

**解説**

【有効数字】「4桁」は小数点以下4桁という意味ではない。最初の0でない数字から数えて4桁を保つ。本問は入力値が正確で、各演算の後に10進有効数字4桁へ四捨五入する。
【途中式】左から計算し、まず1234+1.987=1235.987。これを4桁へ丸めると1236。次に1236−1233=3で、4桁を示すと3.000になる。正解は3。
【誤差】丸めない数学上の答えは2.987。絶対誤差は|3.000−2.987|=0.013、相対誤差は0.013/2.987×100≈0.435%。大きい数の加算時に失った情報が、小さい差を求める場面で目立つ。
【理解のポイント】最後の引算3は、この条件では正確に求まっている。引算の命令が必ず新しい丸め誤差を生むわけではない。式を(1234−1233)+1.987の順に計算できるなら、この例では2.987を保てる。有限桁では式の形と順序も大切である。

## Q 12-5　桁落ち

**問題**

入力値に小さな相対誤差が含まれている場合、差の相対精度を大きく失いやすい演算はどれか。

**選択肢**

1. 正確な2整数の比較
2. ほぼ等しい同符号の2数の減算
3. 桁の異なる2数の乗算だけ
4. どんな2数の加算も同程度

**正答** 2番：ほぼ等しい同符号の2数の減算

**解説**

【意味】ほぼ等しい同符号の数を引くと、共通する大きな桁が消え、小さい差だけが残る。このとき元の数に含まれる小さな誤差が、差に対して大きな割合になることを桁落ちとして問題にする。正解は2。
【具体例】本来の差が1000.01−1000.00=0.01なのに、前者を1000.02として計算すると差は0.02。元の数の誤差0.01は約0.001%にすぎないが、求めたい差の誤差は100%になる。差自体が小さいため、誤差の割合が大きくなる。
【他の選択肢】桁の異なる数の加算で小さい項が消える現象は情報落ちで、近い数の減算とは区別する。どの減算でも同じ程度に精度を失うわけではなく、正確な整数の比較を桁落ちと呼ぶわけでもない。
【対策】必要な精度を確保し、差を直接求めずに済む等価な式へ変える方法もある。重要なのは「引算は悪い」ではなく、「小さい差を求めるとき、入力の精度が足りるか」である。

## Q 12-6　改行コード

**問題**

あるコンパイラがLF改行だけを受け付けると明記されている。CR+LFのソースが拒否された。直接的な対処はどれか。

**選択肢**

1. CPU数を増やす
2. 英数字をすべて別の文字にする
3. 内容を保って改行をLFに変換する
4. 実数の計算を削除する

**正答** 3番：内容を保って改行をLFに変換する

**解説**

【何が違うか】改行は画面では同じように見えても、ファイル内部のコードは同じとは限らない。CRはCarriage Return、LFはLine Feedで、コードはそれぞれ16進で0D、0A。CR+LFは二つを続けたもの、LF改行はLFだけである。
【本問の対応】コンパイラがLFだけを受け付けるという条件なので、文字の内容を保ち、改行形式をLFへ変換する。正解は3。英数字を書き換えたり実数計算を削除したりしても、原因を直せない。CPUを増やすことも無関係。
【作業の例】元ファイルを保存してから、エディターの改行形式をLFにして保存し、再度コンパイルする。改行をすべて削除するのではなく、行の区切りを正しく置き換える。
【区別】UTF-8などの文字コードと、CR/LFの改行形式は別の設定である。両者を確認することはあるが、混同しない。またCR+LFを扱える処理系も多く、すべてのUNIX環境で拒否されるという意味ではない。

## Q 12-7　仮想記憶

**問題**

仮想記憶の説明として適切なのはどれか。

**選択肢**

1. RAM増設と同じ速度を常に実現する仕組み
2. CPUの演算回路そのもの
3. 電源を切っても保持する記憶だけ
4. プロセスの仮想アドレスを物理記憶へ対応付け、保護や必要に応じたページ退避を行う仕組み

**正答** 4番：プロセスの仮想アドレスを物理記憶へ対応付け、保護や必要に応じたページ退避を行う仕組み

**解説**

【仕組み】プログラムが使う住所を仮想アドレス、RAMの実際の住所を物理アドレスと考える。OSとハードウェアが両者を対応付け、各プログラムが使える領域を管理・保護する。これが仮想記憶で、正解は4。
【ページ退避】記憶をページという単位で管理し、必要に応じて一部をディスクへ退避し、必要なときにRAMへ戻す。作業机の上に収まらない資料を棚へ移すイメージである。ただし仮想記憶は、この退避だけでなく、アドレスの管理やプログラム間の保護も含む。
【速度】ディスクへの出し入れはRAM内のアクセスより一般に遅い。頻繁に出し入れすると、計算より待ち時間が長くなることがある。ディスク容量を増やしても、RAMを増設したのと同じ速度にはならない。
【誤答】CPUの演算回路そのものでも、電源を切っても保持する記憶だけでもない。仮想記憶があるから、どんな大きさの解析でも無制限に処理できるわけではない。

## Q 12-8　演算器とキャッシュ

**問題**

説明として誤っているものはどれか。

**選択肢**

1. キャッシュは浮動小数点乗算だけを行う専用回路
2. GPGPUはGPUを汎用的な並列計算に用いる
3. FPUは浮動小数点演算を扱う
4. DSPは積和など信号処理に適した演算を行う

**正答** 1番：キャッシュは浮動小数点乗算だけを行う専用回路

**解説**

【見分け方】「計算する装置」と「データを置く場所」を分ける。キャッシュは、よく使う命令やデータをCPUへ速く渡すための記憶で、浮動小数点乗算だけの専用回路ではない。誤った説明は1。
【各用語】FPUはFloating Point Unitで、小数や非常に大きい・小さい値を扱う浮動小数点演算を担う。DSPはDigital Signal Processorで、信号処理で繰り返す積和などに適した演算を行う。積和とは、a×bのような積を順に足し合わせる処理である。
【GPUの利用】GPGPUは、画像処理用として発達したGPUを一般の計算にも利用する考え方。多数のデータへ似た処理を並行して行う場合に力を発揮する。
【CAEでの注意】GPUへデータを移す時間や、順番にしか実行できない処理もある。ソフトが対応していなければ、GPUを付けるだけで解析が速くなるとはいえない。記憶、演算器、ソフトの役割を分けて理解する。

## Q 12-9　64ビットと精度

**問題**

CPUやOSが32ビットから64ビットへ変わることについて、誤った説明はどれか。

**選択肢**

1. 64ビットCPUでも32ビットの数値形式を使うことがある
2. 同じ浮動小数点形式でも計算精度が必ず2倍になる
3. 扱えるメモリ上限はOS等の条件にも依存する
4. 利用可能なアドレス空間が広がり得る

**正答** 2番：同じ浮動小数点形式でも計算精度が必ず2倍になる

**解説**

【答え】CPUやOSの32ビット・64ビットという分類と、浮動小数点の精度は同じ話ではない。同じ形式で計算するなら、64ビット化だけで有効桁数が必ず2倍になるわけではない。誤りは2。
【精度の例】代表的なIEEE 754形式では、単精度binary32は10進で約7桁、倍精度binary64は約15〜16桁が目安になる。64ビットCPUでも単精度を使うことがあり、32ビットCPUでも倍精度を扱える。
【アドレス】アドレスは記憶の場所を指定する番号。番号に使えるビットが増えると、より広いアドレス空間を扱える可能性がある。32ビットの番号で1バイトずつ指定するなら、2³²バイト=4 GiBが範囲の目安になる。
【限定】実際に使えるメモリは、CPUの実装、OS、アプリケーション、設定などにも制限される。アドレスの範囲が広いこと、搭載RAMが多いこと、数値精度が高いことを別々に確認する。

## Q 12-10　DMAの役割

**問題**

DMAの説明として適切なのはどれか。

**選択肢**

1. 浮動小数点の桁数を増やす回路
2. CPUが全バイトを個別命令でコピーすることだけ
3. DMA機構がCPUの逐次コピーを減らしてデータを転送する
4. ライセンスを配る機能

**正答** 3番：DMA機構がCPUの逐次コピーを減らしてデータを転送する

**解説**

【意味】DMAはDirect Memory Access。CPUがデータを1個ずつコピーする負担を減らし、転送機構にまとまったデータの移動を任せる仕組みである。正解は3。
【仕事の分担】CPUは転送元・転送先・長さなどを設定し、必要に応じて完了を確認する。実際の各データの転送はDMA機構が行う。先生が運ぶ資料を指定し、係がまとめて運ぶような分担と考えられる。CPUが一切関与しない、という意味ではない。
【速くなる理由】CPUが別の計算を進められたり、転送と計算を重ねられたりすると、処理全体を速くできる。CPUの逐次コピーが減ることも利点になる。
【限界と誤答】メモリや転送路の混雑、設定の手間、転送量によって効果は変わる。DMAなら必ず速いとは限らない。浮動小数点の有効桁数を増やす回路でも、ソフトの使用権を配るライセンス管理でもない。数値計算そのものの高速化と、データ転送の効率化を分けて理解する。

## Q 12-11　光ディスクの区別

**問題**

読出専用・追記等の書込可能だが消去して書換え不可・繰返し書換え可能に対応する組合せはどれか。

**選択肢**

1. CD-ROM／CD-R／CD-RW
2. CD-RW／CD-ROM／CD-R
3. CD-R／CD-RW／CD-ROM
4. CD-ROM／CD-RW／CD-R

**正答** 1番：CD-ROM／CD-R／CD-RW

**解説**

【組合せ】読出し専用はCD-ROM、記録できるが記録済み領域を消去・書換えできないのはCD-R、繰返し書換えできるのはCD-RW。したがってCD-ROM／CD-R／CD-RWの順で、正解は1。
【名前の意味】ROMはRead Only Memory、RはRecordable、RWはReWritableを表す。名前と「読むだけ・記録する・書き換える」の違いを結び付けると覚えやすい。
【CD-Rの注意】一度記録した領域を書き直せないことと、ディスク全体への書込み操作が一生に1回だけということは違う。空き領域があり、記録方式や機器などの条件を満たせば、後から追記できる場合がある。
【保存の注意】CD-RWの書換えも無限回できるわけではなく、対応機器が必要である。また、記録方式の名称だけで長期保存の安全性は決まらない。解析データの保管では読めることの確認や、別のバックアップも必要になる。

## Q 12-13　記憶階層

**問題**

CPUと主記憶の速度差を埋めるため、頻用データを保持する高速・小容量の記憶はどれか。

**選択肢**

1. 光ディスク
2. ファイルの圧縮率
3. スワップファイル
4. キャッシュ

**正答** 4番：キャッシュ

**解説**

【正解】キャッシュはCPUの近くに置く高速・小容量の記憶。主記憶RAMから必要なデータを取り込み、再利用しやすくする。CPUとRAMの速度差を埋めるための記憶なので4が正しい。
【身近な例】頻繁に使う工具を手元、予備を引出し、長期保管品を倉庫に置くと作業しやすい。キャッシュ、RAM、SSDやHDDも、このように速さと容量の違う段階を組み合わせる。図はCPUを含む概念図で、記憶の階層そのものはCPU内部のレジスタやキャッシュなどから考える。

## Q 12-14　OSの役割

**問題**

OSの役割はどれか。

**選択肢**

1. プロセス・メモリ・入出力などの資源を管理する
2. ソフトの数値誤差を必ずゼロにする
3. 全業務アプリを標準で含む
4. 構造解析の物理モデルを必ず自動決定する

**正答** 1番：プロセス・メモリ・入出力などの資源を管理する

【意味】OSはOperating Systemで、コンピューターの基本的な働きを管理するソフトウェア。実行中のプログラムであるプロセス、メモリ、ファイル、入出力装置などを管理するので、正解は1。

## Q 12-26　LANとWAN

1. WANは必ず1室だけの通信
2. LANとWANは同義
3. LANは必ず全世界を結ぶ

【例】学校の教室と実習室のPCを校内で結ぶものはLANの例。離れた工場や本社の拠点を結ぶものはWANの例になる。LANとWANを組み合わせて、校内・社内の通信と拠点間通信を行える。
【誤答】LANが必ず全世界を結ぶわけではなく、WANが必ず一室だけに限定されるわけでもない。両者は同じ意味ではない。
【区別】LANは有線だけとは限らず、無線も使う。WANもインターネットだけを指すわけではない。ケーブルか無線か、通信事業者を使うかだけでLAN/WANを決めない。また、LANという名称だけで機密性や利用権限まで保証されるわけではなく、校内・社内でもアクセス管理が必要になる。

## Q 12-27　機密データの送付

**問題**

組織の規定で承認済みの転送方式を使える。機密解析データを相手へ送る適切な対応はどれか。

**選択肢**

1. 記録媒体なら暗号化・輸送管理は一切不要
2. 公開サーバへ無制限で置く
3. 平文メールなら宛先確認は不要
4. 承認方式で暗号化と本人確認・アクセス制限を行い、宛先と送付範囲を確認する

**正答** 4番：承認方式で暗号化と本人確認・アクセス制限を行い、宛先と送付範囲を確認する

**解説**

【答え】承認された方式で暗号化、本人確認、アクセス制限を行い、宛先と送る範囲を確認する4が適切。機密データの送付では「届くこと」だけでなく「許された相手だけが扱えること」が必要になる。
【役割の違い】暗号化は内容を第三者に読まれにくくする。本人確認は相手が意図した人かを確かめる。アクセス制限は許可した人や用途に利用を限定する。暗号化されていても、宛先を取り違えて相手に読める権限を渡せば、誤送信を防げない。
【実務の例】必要なファイルと版だけを選び、送付先、閲覧権限、必要に応じた期限を確認する。解析ファイルに顧客名、設計寸法、不要な別案件の情報が含まれていないかも確認する。
【誤答】公開サーバへの無制限公開は機密管理に反する。平文メールでも宛先確認は必要。記録媒体の配送でも紛失、保管、受取人確認などの管理が必要で、媒体に入れれば安全というわけではない。

## Q 12-28　ネットワークファイル共有

**問題**

遠隔ファイルをファイルシステムとして利用するプロトコルの例はどれか。

**選択肢**

1. RAID
2. NIS
3. NFS
4. CPUの命令セット

**正答** 3番：NFS

**解説**

【答え】NFSはNetwork File System。別の計算機にあるファイルを、ネットワーク越しにファイルシステムとして利用するためのプロトコルで、正解は3。
【使い方のイメージ】サーバの共有領域を自分の計算機へマウントすると、ディレクトリのように扱える。複数の解析用計算機から共通の入力データや結果へアクセスする場面を考えると分かりやすい。実際のアクセスには権限と設定が必要になる。

【注意】ネットワークの速度、サーバの負荷、切断などがファイル操作へ影響する。自分のPC内のファイルと見た目が似ていても、常に同じ速さや可用性ではない。また、RAIDがあることと、誤削除などに備えた別のバックアップがあることも同じではない。

## Q 12-29　ファイル転送

**問題**

名称としてファイル転送を主目的とするプロトコルはどれか。

**選択肢**

1. IMAP
2. FTP
3. SMTP
4. POP3

**正答** 2番：FTP

**解説**

【答え】FTPはFile Transfer Protocolで、ファイル転送を主目的とする。正解は2。名前のTransferと、ファイルを送り受けする役割を結び付ける。
【メールとの違い】SMTPは主にメールの送信・中継、POP3はメールの取得、IMAPはサーバ上のメールへアクセスし管理するために用いる。メールにも添付ファイルはあるが、プロトコルの主な役割はFTPと異なる。
【利用の例】計算用サーバへ入力ファイルを送る、計算後の結果を取得する、といった作業はファイル転送である。一方、結果を知らせるメールを送ることはメール通信である。内容がどちらも解析に関係していても、通信の仕組みは別。
【安全性】FTPという名称だけで暗号化が保証されるわけではない。従来のFTPでは資格情報やデータを平文で扱う場合がある。暗号化を追加するFTPSと、SSHを利用する別のプロトコルSFTPも区別する。機密情報には組織が承認した方式を使い、名称だけで安全と判断しない。

## Q 12-30　並列計算のモデル

**問題**

一般的な並列プログラミングの説明として適切なのはどれか。

**選択肢**

1. OpenMPは全ての分散プロセス間通信を自動で実装する
2. MPIは分散メモリで使えない
3. 自動並列化はどんなコードも無変更で理想加速する
4. MPIはプロセス間通信、OpenMPは主に共有メモリ並列を扱い、併用もできる

**正答** 4番：MPIはプロセス間通信、OpenMPは主に共有メモリ並列を扱い、併用もできる

**解説**

【二つのモデル】共有メモリ型では複数の処理が共通の記憶を使い、分散メモリ型では各計算機などがそれぞれの記憶を持ってデータを交換する。複数人が同じ作業机を使うか、別々の机で作業し資料を渡すかの違いに似る。
【正解】MPIは主にプロセス間の通信を扱う。OpenMPは主に共有メモリ上で複数のスレッドへ仕事を分ける。両者を併用できるので4が正しい。プロセスは独立した実行単位、スレッドは同じプロセス内の実行の流れと考える。
【使い分け】例えば複数の計算機間をMPIでつなぎ、各計算機内をOpenMPで分担する方法がある。MPIは同じ計算機内でも利用でき、共有メモリ機能もある。OpenMPにも追加の機能があり、ここでは代表的な基本モデルを説明している。
【限界】通信、同期、仕事の偏り、前の計算結果を待つ依存関係がある。OpenMPが分散通信を全部自動実装するわけでも、自動並列化がどんなコードでも理想加速するわけでもない。

## Q 12-31　並列効率

**問題**

逐次時間T1=100 s、4プロセッサでの時間T4=40 s。効率η=T1/(4T4)はどれか。

**選択肢**

1. 100%
2. 62.5%
3. 40%
4. 250%

**正答** 2番：62.5%

**解説**

【加速率】逐次時間T₁=100 s、4プロセッサの時間T₄=40 sより、加速率S=T₁/T₄=100/40=2.5。つまり処理時間は元の40%となり、速さは2.5倍になる。
【効率】4台なら理想的には4倍を期待するので、その何割を達成したかをη=S/4で表す。η=100/(4×40)=0.625=62.5%。正解は2。理想的な時間25 sに対し、実測40 sであることとも整合する。
【誤答】40%はT₄/T₁という時間の比。250%は加速率2.5を百分率で表したもの。100%の効率なら本問ではT₄=25 sになる。何の比を取っているかを明確にする。
【速くなり切らない理由】並列にできない部分、通信、同期、仕事の偏りなどがある。ただし100 sと40 sだけから原因の内訳は決められない。比較では同じモデル・計算内容を使い、入出力を含めるかなど計時範囲もそろえる。

## Q 12-32　リバースエンジニアリング

**問題**

ソフトウェアのリバースエンジニアリングの目的の例はどれか。

**選択肢**

1. 既存ソフトを解析せず一から作るだけ
2. 既存の実装から構造・仕様等を理解し、修正や再開発に役立てる
3. 内容を読めなくすることだけ
4. 速度だけを計測することに限定

**正答** 2番：既存の実装から構造・仕様等を理解し、修正や再開発に役立てる

**解説**

【意味】リバースエンジニアリングは、既にある実装や動作を調べ、構造・仕様・設計の考え方を理解する作業。設計から実装へ進む通常の向きと逆にたどるため、この名前がある。正解は2。
【例】説明書が不足した解析用プログラムについて、入力を変えて出力を観察し、利用できるコードを調べる。材料定数の単位や処理の順序を確認し、保守や再開発に必要な仕様を整理する、といった目的が考えられる。
【誤答】何も調べず一から作るだけでは、既存実装を分析する作業にならない。速度測定は分析の一部になり得るが、目的は速度だけに限定されない。内容を読めなくすることは、構造を理解する目的とは異なる。
【実施範囲】調べられる対象や手段は、権利、契約、秘密情報の条件に従う必要がある。仕組みを理解することと、他者のコードを無断で複製・再配布することは別。自分が知りたいという理由だけで、どんな解析や利用でも許されるわけではない。
