# 問題コンテンツ（CAE試験対策）

アプリが読み込む「問題・正解データ」を置く場所。1問＝1レコードのJSON。

## 構造
- `index.json` … 全体の索引（級・章・ファイル・問題数）
- `questions/<級>-<章>.json` … 問題本体（`meta` ＋ `questions[]`）

## 問題レコードのスキーマ
| キー | 型 | 説明 |
|---|---|---|
| `id` | string | 一意ID（例 `solid2-math-1-1`） |
| `number` | string | 問題番号の表示（例 `問1-1`） |
| `question` | string | 問題文 |
| `choices` | string[] | 選択肢（通常4つ） |
| `answer` | number | 正解の選択肢番号（1始まり） |
| `explanation` | string | 解説 |
| `hasMath` | boolean | 数式を含むか（将来の数式表示用フラグ） |
| `figure` | string | 図の要否タグ `"required"｜"helpful"｜"none"`（既定 `none`）。下の運用ルール参照 |
| `figureImage` | string? | `figure="required"` の問だけ付ける図キー（`src/figures.ts` に登録した名前） |
| `figureHint` | string? | その図が「何を示すべきか」の1行メモ（作図・保守用。装飾は描かない） |

## 図解（図）を付けるかの運用ルール【仕組み】
方針（2026-09-12 ユーザー指示で更新）: **初学者がテキストだけの解説で少しでも分かりづらいなら、基本的に図を付ける**。図は理解を助ける主要手段として積極的に使う。
1. **各問に必ず `figure` タグを1つ付ける**。`required`＝図が無いと理解/解答しづらい。`helpful`＝図で理解がぐっと速くなる（**これも図を付ける**）。`none`＝図が純粋に装飾で意味を持たない場合のみ（用語の丸暗記など、ごく少数）。
2. **判定基準**: 「初学者がこの解説をテキストだけで読んで、少しでも詰まりそうか？」詰まりそうなら図を付ける。空間・構造・分布はもちろん、グラフ・行列・ベクトル・数値スキーム・幾何・対応関係なども図にする。
3. **正確さ最優先**: 図はその問の内容と厳密に一致させる。正しく描けない題材に無理な図を付けて誤誘導しない（その場合のみ `none`）。
4. **体裁を統一**: 白地660×420の線画。共通ライブラリ `scratchpad/figlib.py`（arrow/wall/spring/node/bar/支持記号/matrix_grid/axes/plot/iso_box/angle_arc/dim/force 等）で描く。解答の根拠になる要素だけを載せ、飾りの3D風・意味のない色・無関係な全体図は避ける。
5. **図キーは章プレフィクスで命名**（`math*`/`s2*`/`h3*`/`fem*`/`f4*`/`f5*` 等）。`src/figures.ts` の登録は全問JSONの figureImage を走査して自動生成し、未使用キー（幽霊図）を残さない。

## 注意
- 元PDFはスキャン画像のため、OCRではなく画面を読んで手作業でデータ化している。
- 各章の解答は現状「問題編本文からの読み取り」。公式解答冊子（解説編）との照合は別途。
