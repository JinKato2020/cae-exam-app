# オリジナル問題 作成方針（配布可能なCAE対策アプリ）

公式問題集に頼らず、**配布しても著作権上安全な問題**を自作するための設計。
対象: まず「固体力学分野 2級」。他分野・級は同じ枠組みを流用する。

> ⚠️ 私は弁護士ではないので、法的な部分は一般的な整理。最終的な配布前には
> 必要に応じて専門家に確認するのが安全。

---

## 0. 大原則（著作権の線引き）

**守れる（自由に使える）もの＝アイデア・事実・体系**
- 試験の**出題分野・範囲**そのもの（「有限要素法の定式化」等の分野名・トピック）
- **物理法則・数学公式・定義**（フックの法則、応力の釣合い式、差分公式 等）
- 一般的な**知識・概念・解法**

**守れない（真似すると侵害）もの＝具体的な表現**
- 公式問題集の**問題文の言い回し・選択肢の文章・数値の組み合わせ・独自の図**
- それらを**少し言い換えただけのもの**（＝翻案。近すぎるとアウト）

**したがって作成ルールは3つ:**
1. **公式問題集は「見ない・写さない・言い換えない」**。作問時は開かない。
2. **一次情報から作る**：市販の教科書（材料力学・有限要素法・数値解析）、JSMEが公開する
   認定範囲（分野リスト）、自分の理解。これらを土台に**ゼロから自分の言葉で**書く。
3. **非公式である旨を明示**（後述の免責表記）。

---

## 1. 出題範囲の定義（分野の骨組み）

分野名・トピックは「事実」なので使ってよい。固体2級の分野（一般に知られた区分）:

| # | 分野 | 自作問題で問える例（自分の言葉で作る） |
|---|---|---|
| 1 | 計算力学のための数学の基礎 | 行列・行列式・固有値、偏微分、テイラー展開、発散定理、差分公式 |
| 2 | 固体力学の基礎 | 応力・ひずみ、フックの法則、釣合い式、主応力、ミーゼス応力 |
| 3 | 熱伝導の基礎 | 熱伝導方程式、境界条件、定常/非定常 |
| 4 | 有限要素法の定式化 | 重み付き残差法、弱形式、形状関数、要素剛性行列 |
| 5 | 有限要素法の実践 | 全体剛性、境界条件処理、連立方程式の解法 |
| 6 | 数値計算法の基礎 | 直接法/反復法、収束、条件数、数値積分 |
| 7 | 要素テクノロジーの基礎 | 1次/2次要素、アイソパラメトリック、数値積分点 |
| 8 | モデリングの基礎 | 対称性、次元低減（平面応力/ひずみ・軸対称）、要素選択 |
| 9 | 境界条件の使い方の基礎 | 拘束・荷重、剛体変位の排除 |
| 10 | プリポスト処理の基礎 | メッシュ生成、結果可視化、応力の平滑化 |
| 11 | 結果の検証の基礎 | メッシュ収束、理論解との比較、誤差評価 |
| 12 | コンピュータの基礎 | 数値の丸め、浮動小数点、計算量 |
| 13 | 計算力学技術者倫理 | 解析結果の責任、検証の重要性 |

各分野に「**学習目標**（こういう理解を問う）」を自分の言葉で1〜3行つける。これが作問の設計図。

## 2. 問題の「型」を自作する（オリジナル性の鍵）

同じトピックでも、**型（フォーマット）と中身を自分で設計**すればオリジナルになる。

**型の例**
- 4択（概念の正誤・用語の対応）
- 正誤判定（○×）
- 計算問題（数値を入れて答えを出す）
- 穴埋め（式の一部を選ぶ）

**★最強のオリジナル化 = パラメータ化（数値ランダム）計算問題**
数値を変数にして自動生成すれば、**表現も数値も完全に自作**で、無限に増やせる。
例（自作テンプレート）:
- 「2×2 行列 [[a,b],[c,d]] の行列式を求めよ」→ a,b,c,d を乱数で生成、答え=ad−bc
- 「直径 d、荷重 P の丸棒の垂直応力 σ=P/A を求めよ」→ d,P を乱数化
- 「前進差分で f(x)=x² の x=x0 における f′ を刻み h で近似した値は？」

パラメータ化問題は**公式問題集と偶然かぶることがまずなく**、法的に最も安全。
概念系（4択）は、**自分の理解を自分の文章で**書く。既存問題を思い出して書かないこと。

## 3. 作成ワークフロー

```
①分野を選ぶ → ②学習目標を書く → ③型を選ぶ → ④問題を作る
   → ⑤正答を独立に検算 → ⑥オリジナル性チェック → ⑦データ化 → ⑧アプリで確認
```

**作成方法は2案（コスト・品質が変わるので要決定）**
- **A. 手動作成（私と一緒に）**：1問ずつ設計。品質最優先・コスト0（定額内）。量産は遅い。
- **B. LLMで下書き量産＋人手レビュー**：有料API（Claude等）でテンプレから大量下書き→人が検証。
  速いが**有料**。実行前に必ず円換算の見積もりを出して承認をもらう（CLAUDE.md D1）。
  ※LLMにも「公式問題集を参照させない・一次情報とテンプレのみ」を厳守させる。

**パラメータ化問題は③④を「ジェネレータ（コード）」で作る**のが効率的。
1つのテンプレートから実行のたびに別問題が出る＝データを大量に持たなくてよい。

---

## 4. データスキーマの拡張

現行（id/number/question/choices/answer/explanation/hasMath）に、配布・管理用の項目を追加:

| 追加キー | 用途 |
|---|---|
| `topic` / `subtopic` | 分野・細目タグ（範囲カバレッジ管理・出題バランス） |
| `difficulty` | 難易度（1〜3） |
| `type` | `mc`(4択)/`tf`(正誤)/`calc`(計算)/`fill`(穴埋め) |
| `params` / `generator` | パラメータ化問題の変数定義・生成ロジックID |
| `origin` | `original`（自作）を明示。公式由来は載せない |
| `reviewed` | 正答検算・オリジナル性チェック済みか（true/false） |
| `refs` | 根拠（自作メモ・教科書の一般知識。※公式問題集は書かない） |

`origin: "original"` と `reviewed: true` が**揃った問題だけ配布ビルドに含める**。

---

## 5. オリジナル性・品質チェック（配布前の関門）

**各問に対して以下を確認（チェックリスト）**
- [ ] 公式問題集を見ずに作った（言い換えbut近い、になっていない）
- [ ] 数値・選択肢・言い回しが独自
- [ ] 正答を**独立にもう一度**計算/確認した（作問者の思い込み防止）
- [ ] 選択肢の誤答も意味のある「ひっかけ」になっている
- [ ] `origin=original` / `reviewed=true`

**仕組みでの担保**
- 配布ビルドは `reviewed=true && origin==="original"` の問題のみ読み込む（コードで強制）。
- 将来、公式問題(ローカル)との**類似チェック**（テキスト類似度）を回して、偶然の一致を検知。

---

## 6. 免責・法務（アプリ内に必ず表記）

- 「本アプリは**非公式**の学習支援ツールです。JSME（日本機械学会）および公式問題集とは
  **一切関係ありません**。」
- 「掲載の問題はすべて**独自に作成したオリジナル問題**です。」
- 商標（試験名等）は「〜対策」のように**説明的表現**にとどめ、公式ロゴ・名称の誤認を避ける。

---

## 7. 進め方（段階：まずパイロット）

1. **パイロット1分野**（例：1章 数学の基礎）で、**自作10〜20問**（4択＋パラメータ化計算を混ぜる）を作る。
2. 正答検算・オリジナル性チェック → `reviewed=true` 化。
3. アプリ（4択→採点→復習）に載せて動作確認。
4. 問題なければ、他分野へ横展開。

---

## 決定ポイント（次に決めること）
- **作成方法**：A手動（コスト0・高品質・遅い）／ B LLM補助（速い・有料＝要見積もり）
- **初期規模**：パイロットは何問から？（推奨：1分野15問前後）
- **対象分野の順番**：どの分野から作る？（推奨：まず1章 or 得意分野）
