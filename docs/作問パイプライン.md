## 1. 品質基準（第2〜5章と同形式・厳守）

1. **完全オリジナル**。公式標準問題集は著作物なので**写経禁止**。原本はテーマ（何を問うか）の参考のみ。
2. **数式**は KaTeX `$...$`（JSON内はバックスラッシュを `\\` に二重化）。
3. **解説は厚く**、`\n` 区切りで
   - 計算問題: 【基礎】【考え方】【計算】【ポイント】【引っかけ】
   - 概念問題: 【基礎】【考え方】【ポイント】【引っかけ】
   - **各誤答が「どんな勘違いで選ばれるか」を【引っかけ】で必ず説明**。初学者に噛み砕く。
4. `answer` は **1始まり（1〜4）**。**正解分布①②③④をできるだけ均等**にする（偏らせない＝バグ防止）。
5. **計算は必ずPythonで独立検算**し、正解の選択肢と一致を確認。誤答は特定の勘違い（掛け忘れ・単位ミス・符号等）に対応させる。
6. 曖昧な正解・複数正解を作らない。

### 1.5 難易度を落とさないための厳守ルール（2026-09-12・ユーザー厳命／`楽するな`）
**基準(gold standard)＝第2章 `solid-basics.json`・第3章 `heat-basics.json`。新章はこの品質に寄せる。** 今回の診断で見つけた3欠陥を作らない:
- **① 断定語で消せる誤答を作らない**。「必ず/常に/まったく/全く/一切/無視してよい/絶対/同じもので区別する意味はない」等で、内容を知らなくても消せる誤答は禁止。誤答は全て**もっともらしい引っかけ**＝受験者が実際に陥る誤り(公式の掛け忘れ・係数1/2抜け・符号ミス・単位換算ミス・近接概念の取り違え・必要/十分の混同)に対応させ、【引っかけ】で1つずつ説明。
- **② “長さで当たる”構造を作らない**。正解だけ長く詳しい／誤答が短い、を禁止。選択肢の長さ・粒度を揃える。数値誤答は近接値・典型ミス値に。
- **③ 単純問題を減らす**。計算は原則2段階以上(1式代入で終わらせない=系を縮約して解く/2量を組合せる/単位換算を伴う/中間量を経由)。概念問も定義丸暗記でなく「適用・判断・比較」を問う。易問(difficulty 1)は全体の35%以下、計算問題は20%以上。
- **④ 章内・章間の重複を作らない**。同一トピックを重ねない(例: アイソパラ/ヤコビ/積分/ロッキングは第7章に集約、ディリクレ/ノイマンは1問)。
- **⑤ 配置前・コミット前に必ず `python tools/check_quality.py` を通す**(下記§4/§5)。FAIL=修正必須、WARN=しきい値超過なので安易に流さない。**content/questions/*.json を書き換えると自動でこのチェッカーが走る**(PostToolUseフック `~/.claude/hooks/cae-quality-check.mjs`。次セッションから有効)。

## 3. 図の仕組み（積極方針・2026-09-12更新）

**初学者がテキストだけの解説で少しでも分かりづらいなら、基本的に図を付ける**（詳細は content/README.md）。
- `required`＝図が無いと理解しづらい / `helpful`＝図で理解がぐっと速くなる（**これも図を付ける**） / `none`＝純粋に装飾になる場合のみ（ごく少数）。
- **正確さ最優先**。正しく描けない題材に無理な図を付けない。
- 図は白地660×420線画。**共通ライブラリ `tools/figlib.py` で描く**（体裁統一）。キーは章接頭辞（`math*`/`s2*`/`h3*`/`f4*`/`f5*`、6章は `num6*`、7章は `elem7*` を推奨）。

## 4. 恒久ツール（`tools/`）

| ツール | 役割 | 使い方 |
|---|---|---|
| `tools/figlib.py` | 図の共通描画API（arrow/wall/spring/node/bar/pin_support/roller_support/matrix_grid/axes/plot/iso_box/angle_arc/dim/force/title/note、白地660x420） | 図スクリプトの冒頭で `import sys; sys.path.insert(0, r"<toolsの絶対パス>"); from figlib import *`。`new()`→描画→`save(im,"キー")` で `assets/figures/キー.png` に保存 |
| `tools/gen_figures_ts.py` | 全問題JSONの `figureImage` を走査して `src/figures.ts` を**自動生成**。幽霊/欠落PNGも検出 | `python tools/gen_figures_ts.py`（図キーを足したら必ず実行。手でfigures.tsを編集しない） |
| `tools/build_pdfs.py` | 各章を「問題・解答・解説・図」入り**PDF**でプロジェクト直下に出力（数式=MathJax、図=base64、Edge headless） | `python tools/build_pdfs.py 6 7`（無指定で1〜5章）。新章は `FILES` 辞書に追記 |
| `tools/build_preview.py` | 任意の問題JSONを**ブラウザ確認用の自己完結HTML**に変換（数式=MathJax、図=base64埋め込み、【…】節整形、答え/解説トグル）。出力を **Artifactツールでpublishすれば別端末でも確認可**（publishは本体が行う） | `python tools/build_preview.py content/questions/<file>.json`（章番号や無指定=全章も可）。出力先 `preview/<stem>.html` |
| `tools/check_quality.py` | **作問の難易度・品質ゲート**。§1.5の欠陥(断定語で消せる誤答・“長さで当たる”・易問過多/計算過少・章内外の重複・図欠落・構造)を機械検出しPASS/WARN/FAIL判定。基準=第2/3章がPASSになるよう較正済 | `python tools/check_quality.py`(全章) / `python tools/check_quality.py content/questions/xxx.json`(1章)。**content/questions/*.json を書くと自動起動**(PostToolUseフック) |

図キー注入（agentが図を描いた後、JSONに `figureImage` を入れる）の定番スクリプトは §6 に雛形あり。

## 5. 手順（章1つを作る/直す）

1. **原本トピック要約**（任意）: `_原本(非公開)/固体2級標準問題集/<章>.pdf` を**1体のサブエージェントでトピックのみ要約（逐語禁止）**。総問数と各問テーマ・種別を把握。スキャンPDFはOCR不可なので画像で読む。
2. **作問**: 章ごとに1体のサブエージェントで全問をJSONドラフト（§7雛形）。scratchpadへWrite。自己検算まで。
3. **本体で独立検証**: Pythonで①構造（問数・answer1-4・選択肢4・figureタグ）②答え分布③**計算問題の全文を抽出して自分で再計算**（§6）。**さらに `python tools/check_quality.py content/questions/<file>` を実行し、§1.5の欠陥がFAIL/WARNで出ないか確認**（配置後にもフックが自動で走る）。WARNは安易に見逃さず、基準(第2章)の品質かを目視で判断。
4. **図**: 章ごとに1体のサブエージェントが `tools/figlib.py` で図を描き（§8雛形）、PNGとマップ `{番号:{key,tag,hint}}` を出力。**JSON本体はagentに触らせない**。
5. **注入**: 本体が §6 のinjectでマップをJSONへ反映（figureImage/figure/figureHint）。既存figureImageは上書きしない。
6. **figures.ts再生成**: `python tools/gen_figures_ts.py`（欠落0・幽霊0を確認。幽霊PNGは削除）。
7. **索引更新**: `content/index.json` の該当章 `count`（と新章なら `src/catalog.ts` に章追加）。
8. **ブラウザ確認（推奨・恒久ツール）**: `python tools/build_preview.py content/questions/<file>.json` で自己完結HTML（数式MathJax・図base64埋込・解説トグル）を `preview/<stem>.html` に生成 → **本体がArtifactツールでpublish**（別端末でも確認可・同URL更新は`url`指定）。PDFが要るときのみ `python tools/build_pdfs.py <章>`。
9. **ユーザー確認 → commit/push**。ビルドは E3（iOS日次上限）に注意し要相談。

## 7. 作問サブエージェントのプロンプト雛形（コピーして使う）

> 出力先: `<scratchpad>\chN_draft.json`。スキーマは docs/作問パイプライン.md §2 の通り。
> 解説は厚く【基礎/考え方/(計算)/ポイント/引っかけ】、数式は KaTeX `$...$`（JSON内は `\\`）。`answer`は1始まりで**①②③④を均等**に。計算は最後まで解いて正解一致を確認、誤答は特定の勘違いに対応。

## 8. 図追加サブエージェントのプロンプト雛形

> 第N章の既存問題に図を追加する。`tools/figlib.py` を `import sys; sys.path.insert(0, r"<toolsの絶対パス>"); from figlib import *` で読み込み、`new()`→描画→`save(im,"<接頭辞>Xxx")`。
