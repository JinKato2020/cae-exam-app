## 1. 品質基準（第2〜5章と同形式・厳守）

1. **完全オリジナル**。公式標準問題集は著作物なので**写経禁止**。原本はテーマ（何を問うか）の参考のみ。
2. **数式**は KaTeX `$...$`（JSON内はバックスラッシュを `\\` に二重化）。
3. **解説は厚く**、`\n` 区切りで
   - 計算問題: 【基礎】【考え方】【計算】【ポイント】【引っかけ】
   - 概念問題: 【基礎】【考え方】【ポイント】【引っかけ】
   - **各誤答が「どんな勘違いで選ばれるか」を【引っかけ】で必ず説明**。初学者に噛み砕く。
4. `answer` は **1始まり（1〜4）**。**正解分布①②③④をできるだけ均等**にする（偏らせない＝バグ防止）。
5. **計算は必ずPythonで独立検算**し、正解の選択肢と一致を確認。誤答は特定の勘違い（掛け忘れ・単位ミス・符号等）に対応させる。
6. 曖昧な正解・複数正解を作らない。

### 1.5 難易度を落とさないための厳守ルール（2026-09-12・ユーザー厳命／`楽するな`）
**基準(gold standard)＝第2章 `solid-basics.json`・第3章 `heat-basics.json`。新章はこの品質に寄せる。** 今回の診断で見つけた3欠陥を作らない:
- **① 断定語で消せる誤答を作らない**。「必ず/常に/まったく/全く/一切/無視してよい/絶対/同じもので区別する意味はない」等で、内容を知らなくても消せる誤答は禁止。誤答は全て**もっともらしい引っかけ**＝受験者が実際に陥る誤り(公式の掛け忘れ・係数1/2抜け・符号ミス・単位換算ミス・近接概念の取り違え・必要/十分の混同)に対応させ、【引っかけ】で1つずつ説明。
- **② “長さで当たる”構造を作らない**。正解だけ長く詳しい／誤答が短い、を禁止。選択肢の長さ・粒度を揃える。数値誤答は近接値・典型ミス値に。
- **③ 単純問題を減らす**。計算は原則2段階以上(1式代入で終わらせない=系を縮約して解く/2量を組合せる/単位換算を伴う/中間量を経由)。概念問も定義丸暗記でなく「適用・判断・比較」を問う。易問(difficulty 1)は全体の35%以下、計算問題は20%以上。
- **④ 章内・章間の重複を作らない**。同一トピックを重ねない(例: アイソパラ/ヤコビ/積分/ロッキングは第7章に集約、ディリクレ/ノイマンは1問)。
- **⑤ 配置前・コミット前に必ず `python tools/check_quality.py` を通す**(下記§4/§5)。FAIL=修正必須、WARN=しきい値超過なので安易に流さない。**content/questions/*.json を書き換えると自動でこのチェッカーが走る**(PostToolUseフック `~/.claude/hooks/cae-quality-check.mjs`。次セッションから有効)。

### 1.6 公式標準問題との1:1対応・番号参照・著作権の厳守ルール（2026-09-15・ユーザー厳命／永久方針）
アプリは「公式標準問題集を片手に使う補助教材」。中心は公式、アプリは2次的。ただし補助として重要（スキマ時間の反復・図/用語/公式の多角的理解・重い公式教材を携帯できない弱点を補う）。目的＝難しすぎる公式解説を、アプリで学ぶことで理解できるようにする。
- **① 1:1対応が最優先。** 各章、公式標準問題 1..N に対しアプリ問題も同番号で 1..N を用意（例: 公式 `10-1`↔アプリ1問目、`10-21`↔21問目）。サブ節のある章は公式ラベルを保持しつつアプリ連番に対応づける（例: `11(1)-1`↔1問目… は**表記スタイルの例**であり「11章＝10問」の意味ではない。各章の実際の問題数は必ず公式標準問題を参照）。→ユーザーが公式を片手にアプリを引ける。
- **② アプリの標準問題数は公式を決して超えない。** 本番は公式標準問題から出題と明示。標準問題として公式Nを超える新番号は作らない。
- **③ 超過分は捨てず「枝問/補足」化。** 既存章で公式より多い問題は、対応する公式番号にぶら下げる補足として温存（標準番号を超えない）。1:1を優先しつつ深掘りを残す。
- **④ 番号参照はOK・中身は完全オリジナル。** 公式問題番号（`1-1` 等）を参照ラベルとして併記するのは低リスク（番号＝索引/引用）。ただし問題文・選択肢・図・解説の写経/微改変は禁止（§1-1と同じ）。問題の選定・配列の丸ごと再現もしない（編集著作物への配慮）。
- **⑤ 非提携を明示。** 「本アプリは非公認の独自補助教材。公式問題番号は対応学習の便宜のための参照」の一言をアプリ内1か所に置く。
- **⑥ 但し書き。** 確実性が要る場合は公式標準問題集の利用規約・許諾条件を一度確認する（公開・課金は不可逆／CLAUDE.md 0-3。法律家の確認ではなく一般論）。

## 3. 図の仕組み（積極方針・2026-09-12更新）

**初学者がテキストだけの解説で少しでも分かりづらいなら、基本的に図を付ける**（詳細は content/README.md）。
- `required`＝図が無いと理解しづらい / `helpful`＝図で理解がぐっと速くなる（**これも図を付ける**） / `none`＝純粋に装飾になる場合のみ（ごく少数）。
- **正確さ最優先**。正しく描けない題材に無理な図を付けない。
- 図は白地660×420線画。**共通ライブラリ `tools/figlib.py` で描く**（体裁統一）。キーは章接頭辞（`math*`/`s2*`/`h3*`/`f4*`/`f5*`、6章は `num6*`、7章は `elem7*` を推奨）。

## 5. 手順（章1つを作る/直す）

1. **原本トピック要約**（任意）: `_原本(非公開)/固体2級標準問題集/<章>.pdf` を**1体のサブエージェントでトピックのみ要約（逐語禁止）**。総問数と各問テーマ・種別を把握。スキャンPDFはOCR不可なので画像で読む。

6. **figures.ts再生成**: `python tools/gen_figures_ts.py`（欠落0・幽霊0を確認。幽霊PNGは削除）。
7. **索引更新**: `content/index.json` の該当章 `count`（と新章なら `src/catalog.ts` に章追加）。
8. **ブラウザ確認（推奨・恒久ツール）**: `python tools/build_preview.py content/questions/<file>.json` で自己完結HTML（数式MathJax・図base64埋込・解説トグル）を `preview/<stem>.html` に生成 → **本体がArtifactツールでpublish**（別端末でも確認可・同URL更新は`url`指定）。PDFが要るときのみ `python tools/build_pdfs.py <章>`。

## 10. 固体1級「章まるごと」手順（問題＋解説＋公式・用語＋アプリ＋ビルド）

### 10-0 原本を読む（問題編＋解説編の両方）【今回の追加】

## 11. 公式・用語の仕組み
- **データ**: `content/formulas/solid1-ch<章>.json`。スキーマ:
  `{ "grade":"1級", "chapter":N, "title":"第N章 …", "intro":"…", "items":[ {"id","kind":"formula"|"term","term","formula"(任意・KaTeX・JSON内は\\で二重化),"body","example"(任意),"figureImage":"s1f<章>Xxx"} ] }`
  **`grade` フィールドで級を判別**（`build_formula_pdfs.py` が出力先 `アプリ/<級>/` とサブタイトルを切替。2級ファイルには無く既定"2級"）。
- **図**: 公式専用図は接頭辞 **`s1f<章>`** で `tools/figlib.py`（白地660×420線画・機構だけ描く・装飾禁止）。豆腐(□)は上/下付きや⟂等がMeiryoに無い時に出る→通常表記（`B^T`,`Ke`,`Ni`,`法線が垂直`等）に置換。`gen_figures_ts.py` が公式JSONも走査し `src/figures.ts` に登録＝アプリでも表示される。
- **PDF**: `python tools/build_formula_pdfs.py solid1-ch9`（引数: 数字=2級ch／ファイル名stem=任意JSON。無指定=2級全13章）。数式=MathJax・図=base64・Edge headless。
- **内容方針**: 2級と同水準の初学者向け（噛み砕く・数値例・図）。難易度を落とさない。

## 12. アプリ実装（1級の章を出す）
アプリは `src/catalog.ts`（分野→級→章）を `App.tsx` の `COURSES` が読む。「固体力学 1級」コースは有効済みで、各章は `ready` フラグで出し分け（準備中は自動グレーアウト）。ある章を出す手順:
1. **catalog.ts**: 冒頭で `import s1ch9 from '../content/questions/solid1-09-…json'`。g1 の該当プレースホルダ（`s1stub(9,…)`）を実データに差し替え:
   `{ id:'ch9', title:'第9章 数値解析法', data: s1ch9 as unknown as Chapter, ready:true, formulaId:'s1ch9' }`
   （`ChapterEntry` の任意フィールド: `ready?`＝使えるか、`formulaId?`＝公式キー）。
2. **formulas.ts**: `import s1ch9 from '../content/formulas/solid1-ch9.json'` ＋ `FORMULA_DOCS` に `s1ch9: s1ch9 as unknown as FormulaDoc`。**キーは catalog の `formulaId` と一致**（2級 `ch9` と衝突させないため `s1ch9`）。
3. `python tools/gen_figures_ts.py`（`s1e9`＋`s1f9` を figures.ts に登録・欠落/幽霊0確認）。
4. `npm run tsc`（初回は `npm install`。`react-native-svg` はHUD必須・残す）。
5. UIは 問題タブ=課程→章→タイル→問題／公式タブ=課程→章→項目。準備中章は非活性。
